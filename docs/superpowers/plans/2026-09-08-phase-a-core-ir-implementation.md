# MarkItDown 2Ways Phase A Core IR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the dependency-light, deterministic, validated `markitdown.twoways` Core IR substrate without changing existing MarkItDown conversion behavior.

**Architecture:** Add an isolated `markitdown.twoways` namespace using standard-library dataclasses and explicit serializers. The core owns value models, validation, deterministic JSON, typed edit/fidelity results, reader/writer protocols, and an upstream-compatible priority registry; format-specific PPTX/DOCX/XLSX/PDF code remains out of Phase A.

**Tech Stack:** Python 3.10+, stdlib `dataclasses`, `typing`, `json`, `hashlib`, `math`, `enum`; pytest; existing MarkItDown mypy/Hatch configuration.

**Spec:** `docs/superpowers/specs/2026-09-08-markitdown-2ways-phase-a-core-ir-design.md`

## Global Constraints

- First schema version is exactly `0.1.0` with schema name `MarkItDown2WaysDocument`.
- New production code lives under `packages/markitdown/src/markitdown/twoways/`.
- Existing `_markitdown.py`, `_base_converter.py`, converters, CLI behavior, and existing plugin semantics remain unchanged in Phase A.
- Core modules must not import `pptx`, Mammoth, Pandas, OpenPyXL, LibreOffice, Node.js bridges, Docling, or cloud SDKs.
- No random UUIDs, timestamps, environment-dependent paths, network access, or binary blobs are generated by canonical serialization.
- Registry semantics match upstream: lower priority first; for equal priority, most recently registered implementation first.
- Invalid graph/reference structures fail closed with `IRValidationError` and structured violations.
- Public import is explicit through `markitdown.twoways`; no root-package re-export is required in Phase A.
